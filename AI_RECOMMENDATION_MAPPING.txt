🎯 THE MAPPING:
─────────────────────────────────────────────────────────────────────────────

AI Returns                  App Status              What It Means
─────────────────────────────────────────────────────────────────────────────
"recommend-approve"   →   ✅ OFFICER CAN APPROVE  AI says clear violation
"recommend-reject"    →   ✅ OFFICER CAN REJECT   AI says no violation  
"needs-human-judgment"→   ⚠️  OFFICER MUST REVIEW  AI is uncertain/borderline
"screen-out-irrelevant"→  ❌ FILTERED OUT         Not about reported violation


🔄 THE FLOW (Step by Step):
─────────────────────────────────────────────────────────────────────────────

1️⃣  CITIZEN SUBMITS REPORT
    Input: Image + violation_type + location
    
2️⃣  AI PROCESSES (ASYNC - Background)
    OpenAI/Gemini analyzes image
    Returns JSON with recommendation field:
    {
      "recommendation": "recommend-approve",  ← THIS VALUE
      "relevance_confidence": 92,
      "violation_confidence": 85,
      ...
    }
    
3️⃣  APP STORES AI RESULT
    Database saves:
    {
      "ai_state": "completed",
      "ai_outcome": {
        "recommendation": "recommend-approve",  ← STORED AS-IS
        "relevance_confidence": 92,
        "violation_confidence": 85,
        ...
      }
    }
    
4️⃣  OFFICER VIEWS REPORT
    GET /api/authority/reports/{id}
    Response includes:
    {
      "report_id": "abc123",
      "status": "awaiting-review",
      "ai": {
        "job_id": "job123",
        "state": "completed",
        "outcome": {...},
        "recommendation": "recommend-approve",  ← DISPLAYED TO OFFICER
        "failure_code": null,
        "processing_ms": 5432
      },
      "assessment": {
        "recommendation": "recommend-approve",
        "relevance": "relevant",
        "violation_confidence": 85,
        "explanation": "Clear helmet violation visible",
        "observations": [...]
      }
    }
    
5️⃣  OFFICER SEES UI:
    ┌─────────────────────────────────────────────┐
    │ 🤖 AI Assessment Status                      │
    ├─────────────────────────────────────────────┤
    │ Recommendation: ✅ Recommend Approve        │
    │ Violation Confidence: 85%                   │
    │ Relevance: relevant                         │
    │                                             │
    │ Explanation:                                │
    │ "Clear helmet violation visible..."         │
    │                                             │
    │ Observations:                               │
    │ - "Rider visible on motorcycle with no      │
    │   helmet protection"                        │
    │ - timestamp: N/A (image, not video)         │
    ├─────────────────────────────────────────────┤
    │ [APPROVE]  [REJECT]  [REQUEST INFO]         │
    └─────────────────────────────────────────────┘
    
6️⃣  OFFICER MAKES DECISION
    Officer clicks "APPROVE" (can ignore AI recommendation if wanted)
    
7️⃣  APP UPDATES REPORT
    Database updates:
    {
      "status": "approved",
      "provisional_points": 2,          ← OFFICER AWARDS THIS, NOT AI
      "updated_at": "2026-11-13T16:21:00Z"
    }
    
8️⃣  CITIZEN SEES RESULT
    GET /api/reports/{id}
    Reports sees:
    {
      "status": "approved",
      "provisional_points": 2
    }

🎯 CRITICAL: NO DIRECT ENUM USAGE IN APP
─────────────────────────────────────────────────────────────────────────────

The app does NOT use recommendation to FORCE any action:

❌ WRONG:
  if ai.recommendation == "recommend-approve":
    report.status = "approved"           ← AI can't approve!
    report.points = 2                    ← AI can't award points!

✅ CORRECT:
  if ai.recommendation == "recommend-approve":
    display_ui_text = "Recommend Approve"  ← Just show to officer
  
  // Officer clicks button
  officer.clicks_approve()
  
  // Then app does:
  report.status = "approved"
  report.points = 2                      ← OFFICER awards, not AI


📋 HOW DATA FLOWS IN REAL EXAMPLE:
─────────────────────────────────────────────────────────────────────────────

1. OpenAI API returns:
   {
     "relevance": "relevant",
     "recommendation": "recommend-approve",     ← STRING FROM API
     "violation_confidence": 82,
     ...
   }

2. App stores in ai_jobs table:
   {
     "assessment": "{...\"recommendation\": \"recommend-approve\"...}"  ← JSON STRING
   }

3. App fetches and deserializes:
   assessment = json.loads(row['assessment'])
   recommendation = assessment['recommendation']  ← Python string value

4. JobStore returns:
   {
     "recommendation": "recommend-approve"  ← Still a string
   }

5. Officer page receives:
   {
     "ai": {
       "recommendation": "recommend-approve"  ← JSON string
     }
   }

6. Frontend JavaScript checks:
   if (aiData.recommendation === "recommend-approve") {
     showApproveButton();
   }

7. Officer clicks button:
   POST /api/authority/reports/{id}/decision
   {
     "action": "approve"         ← Officer's action, NOT from AI
   }

8. Final result in database:
   {
     "status": "approved",       ← Set by officer's action
     "provisional_points": 2     ← Set by POINTS_BY_VIOLATION[violation_type]
   }


🚨 IMPORTANT: AI RECOMMENDATION IS ONLY ADVISORY
─────────────────────────────────────────────────────────────────────────────

Timeline:
  AI says "recommend-approve" (85% confidence)
                ↓
  Officer reviews image
                ↓
  Officer thinks "Actually, this could be a turban (religious exemption)"
                ↓
  Officer clicks "REJECT"  ← OVERRIDES AI
                ↓
  Report status = "rejected"  ← Officer's decision wins

✨ KEY INSIGHT:
─────────────────────────────────────────────────────────────────────────────

The AI recommendation field is a STRING VALUE, NOT an ENUM that the app uses.

The app:
  1. Receives it from AI
  2. Stores it as-is
  3. Displays it to officer (for advisory purposes)
  4. Officer makes final decision (completely independent of recommendation)

The enum is purely for AI output validation (schema) and UI display.
