### M4.2: API Endpoints (app.py)
**Lines Added:** ~440 lines (6 endpoint handlers + points mapping)  
**Status:** 6/6 endpoints implemented, 3/10 tests PASS, 7/10 SKIPPED (fixture params needed)

#### Endpoints Implemented

**1. POST /api/reports (201 Created)**
- **Actor:** Citizen
- **Request:** `{violation_type, location, media_id}`
- **Response:** `{report_id, status, violation_type, created_at, citizen_id}`
- **Validation:** Missing fields → 400, invalid violation → 400, media not found → 404
- **Authorization:** X-Citizen-Id header required

**2. GET /api/reports (200 OK, Paginated)**
- **Actor:** Citizen
- **Params:** `page=1&page_size=20`
- **Response:** `{reports[], total_count, page, page_size}`
- **Access Control:** Only citizen's own reports visible
- **Ordering:** By created_at DESC (newest first)

**3. GET /api/reports/{id} (200 OK)**
- **Actor:** Citizen
- **Response:** Full report + timeline events in chronological order
- **Access Control:** Only citizen who created report can view
- **Denials:** 403 if citizen doesn't match, 404 if not found

**4. POST /api/reports/{id}/clarification (200 OK)**
- **Actor:** Citizen
- **Request:** `{clarification_text, new_media_id}`
- **Response:** `{report_id, status='resubmitted', clarification_event}`
- **Precondition:** status must be 'awaiting-citizen-info' (409 if not)
- **Event:** Creates "clarification" event with old/new status

**5. GET /api/authority/reports (200 OK, Paginated)**
- **Actor:** Officer
- **Params:** `page=1&page_size=10&status=awaiting-review` (optional filter)
- **Response:** `{reports[], total_count, page, page_size, total_pages, media_count per report}`
- **Authorization:** Requires "Authorization" or "X-Reviewer-Token" header (401 if missing)
- **Default Filter:** status IN ('awaiting-review', 'resubmitted')
- **Ordering:** By created_at ASC (FIFO queue)

**6. POST /api/authority/reports/{id}/decision (200 OK)**
- **Actor:** Officer
- **Request:** `{action: "approve"|"reject"|"request-info", reason?}`
- **Precondition:** status must be 'awaiting-review' (409 if not)
- **Three Paths:**
  - **Approve:** Award provisional_points, set status='approved'
  - **Reject:** Set status='rejected', store reason in event
  - **Request-Info:** Set status='awaiting-citizen-info' (requeues to citizen)
- **Points Mapping:** helmet=2, triple-riding=3, red-light=3 (hardcoded for MVP)
- **Event:** Creates "decision" event with actor='officer', new_status, reason, provisional_points

#### Implementation Details

**Points Award Logic**
```python
POINTS_BY_VIOLATION = {
    "helmet": 2,
    "triple-riding": 3,
    "red-light": 3
}
```
Simple hardcoded mapping (no time-decay, location adjustment, or escalation in MVP).

**Identity Middleware** (Existing from M2)
- `X-Citizen-Id` header required for all citizen endpoints
- Demo-only (forged headers allowed in MVP, not production-grade)
- Officer endpoints use "Authorization" or "X-Reviewer-Token" header

**Database Transactions**
- All endpoints wrap operations in atomic transactions
- Events are immutable (append-only, never UPDATE events table)
- Status changes via UPDATE reports + INSERT events (atomic)

**Pagination**
- OFFSET/LIMIT SQL for efficient large result sets
- page=1 always first; boundary cases handled (page > total_pages returns empty list)
- total_pages calculated as `(total_count + page_size - 1) // page_size`

**Error Responses**
- 400: Invalid input (missing fields, invalid violation type, bad pagination)
- 401: Missing authorization header
- 403: Access denied (citizen trying to access other citizen's report)
- 404: Resource not found (report, media)
- 409: Conflict (wrong status for operation, duplicate media)
- 422: Unprocessable (corrupted media)
- 500: Internal server error (database issues, caught and logged)

## 🚧 Known Limitations & Caveats

### Test Coverage Gaps
1. **Media endpoint not yet wired** — M4.2 endpoints don't call media.py handler
   - POST /api/reports accepts media_id but doesn't validate it belongs to citizen
   - Media upload endpoint (PUT /api/reports/{id}/media) not yet implemented
   - **Workaround:** conftest.py sample_media fixture inserts directly into DB

2. **Officer authorization** — Endpoints check for header but don't validate token
   - No JWT validation, no OIDC integration (M5 responsibility)
   - Any request with "Authorization" header is accepted
   - **Workaround:** Demo mode; production requires OAuth middleware

3. **Points calculation** — Hardcoded mapping only
   - No time-based decay (e.g., multiple violations in one day)
   - No location-based adjustments
   - No escalation beyond provisional points
   - **Workaround:** Sufficient for MVP demo; Phase 2 adds complexity

4. **Pagination off-by-one edge cases** — Not exhaustively tested
   - Boundary: page > total_pages (returns empty list)
   - Boundary: page_size=0 (returns error)
   - **Workaround:** Works for typical use cases; unit tests needed for edge cases

### Performance Notes
- SQLite file-based storage fine for MVP (single-user, single-writer)
- No connection pooling config (single connection per request)
- Pagination using OFFSET/LIMIT (OK for <10K records; poor for million-row tables)
- No indexes on frequently-searched columns (e.g., citizen_id, status)
- **Phase 2 Improvement:** Add indexes, migrate to PostgreSQL with better pooling
